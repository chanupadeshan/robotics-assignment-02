# TurtleBot3 Autonomous Maze Navigation

Autonomous navigation of a **TurtleBot3 Burger** in a custom maze using **ROS 2 Jazzy** and **Gazebo Harmonic**. The project will cover LiDAR-based SLAM, Nav2 goal navigation, Deep Q-Learning (DQN), and a comparison of the navigation approaches.

> **Project status:** Custom Gazebo maze and TurtleBot3 simulation dependencies are set up. ROS topics `/scan`, `/odom`, `/cmd_vel`, and `/joint_states` have been discovered. Sensor message rates, manual driving, SLAM, Nav2, and DQN still need to be validated or implemented.

## 1. Requirements

- Ubuntu **24.04 LTS (Noble)**, 64-bit
- ROS 2 **Jazzy**
- Gazebo **Harmonic** (Gazebo Sim 8)
- TurtleBot3 **Burger**
- Python **3.12** (system Python for ROS 2)
- `colcon`, Git, and ROS–Gazebo integration (`ros_gz`)

No Python `.venv` is needed to build or run the ROS 2 packages. An independent PyTorch environment may be used for **standalone DQN training** later; it should not replace the ROS 2 system Python.

## 2. Install ROS 2 Jazzy

Follow the official Ubuntu 24.04 installation instructions to configure the signed ROS APT repository:

https://docs.ros.org/en/jazzy/Installation/Ubuntu-Install-Debs.html

Once the repository is configured:

```bash
sudo apt update
sudo apt install -y \
  ros-jazzy-desktop \
  python3-colcon-common-extensions \
  python3-rosdep \
  git
```

Initialize the shell environment and verify ROS 2:

```bash
source /opt/ros/jazzy/setup.bash
ros2 --help
```

If `rosdep` is not initialized on a fresh machine, run `sudo rosdep init` (once), then `rosdep update`.

## 3. Install Gazebo Harmonic and TurtleBot3 dependencies

ROS 2 Jazzy's supported Gazebo pairing is **Harmonic**. Install the Gazebo integration, TurtleBot3, SLAM, and Nav2 packages:

```bash
sudo apt update
sudo apt install -y \
  ros-jazzy-ros-gz \
  ros-jazzy-robot-state-publisher \
  ros-jazzy-xacro \
  ros-jazzy-turtlebot3 \
  ros-jazzy-turtlebot3-description \
  ros-jazzy-turtlebot3-gazebo \
  ros-jazzy-turtlebot3-msgs \
  ros-jazzy-slam-toolbox \
  ros-jazzy-navigation2 \
  ros-jazzy-nav2-bringup
```

Verify Gazebo and the main ROS packages:

```bash
source /opt/ros/jazzy/setup.bash
gz sim --versions

for pkg in ros_gz_sim ros_gz_bridge turtlebot3_gazebo \
           turtlebot3_description xacro slam_toolbox nav2_bringup; do
  if ros2 pkg prefix "$pkg" >/dev/null 2>&1; then
    echo "[OK] $pkg"
  else
    echo "[MISSING] $pkg"
  fi
done
```

> **Repository troubleshooting (specific to the original setup):** The original `packages.ros.org` HTTPS endpoint produced a TLS hostname/certificate mismatch. Switching the ROS source URL to the Tsinghua HTTPS mirror made ROS packages discoverable. **Do not disable TLS verification.** On machines using `/etc/apt/sources.list.d/ros2.list`, the existing source can be backed up and changed with:
>
> ```bash
> sudo cp /etc/apt/sources.list.d/ros2.list /etc/apt/sources.list.d/ros2.list.bak
> sudo sed -i 's|https://packages.ros.org/ros2/ubuntu|https://mirrors.tuna.tsinghua.edu.cn/ros2/ubuntu|g' /etc/apt/sources.list.d/ros2.list
> sudo apt update
> ```
>
> This is optional and **only applies if that `.list` file exists**. Modern ROS installs can use a `.sources` file instead. Unrelated APT warnings (such as a Syncthing certificate failure) must be handled separately.

## 5. Build the workspace

Use the location of your cloned or copied project. For the original development machine:

```bash
cd /mnt/storage/Projects-external/robotics/turtlebot3_maze_ws
source /opt/ros/jazzy/setup.bash

colcon build --packages-select maze_world \
  --cmake-args \
  -DPython3_EXECUTABLE=/usr/bin/python3 \
  -DPYTHON_EXECUTABLE=/usr/bin/python3

source install/setup.bash
ros2 pkg prefix maze_world
```

The `maze_world/CMakeLists.txt` file must install its Gazebo assets:

```cmake
install(
  DIRECTORY launch worlds models
  DESTINATION share/${PROJECT_NAME}
)
```

Place this block immediately before `ament_package()`.

**Python build troubleshooting:** If CMake tries to use `~/.local/bin/python3` and reports `No module named 'catkin_pkg'`, confirm `/usr/bin/python3 -c 'import catkin_pkg'` succeeds, then clear the package's cached build before retrying:

```bash
rm -rf build/maze_world install/maze_world
```

Do not delete the `src/maze_world` directory.

## 6. Validate and run the maze

Check the SDF file first:

```bash
gz sdf -k /mnt/storage/Projects-external/robotics/turtlebot3_maze_ws/src/maze_world/worlds/maze.sdf
```

Expected result: `Valid.`

For this machine, Gazebo Transport discovery worked when **both terminals** used `GZ_IP=127.0.0.1` and the same `GZ_PARTITION`. These settings are useful for single-machine development, but should be changed if multiple computers need to communicate.

### Terminal 1 — Gazebo server

```bash
source /opt/ros/jazzy/setup.bash
export GZ_PARTITION=robotics_test
export GZ_IP=127.0.0.1
export GZ_SIM_RESOURCE_PATH="/opt/ros/jazzy/share/turtlebot3_gazebo/models:${GZ_SIM_RESOURCE_PATH:-}"

gz sim -s -r -v 4 \
  /mnt/storage/Projects-external/robotics/turtlebot3_maze_ws/src/maze_world/worlds/maze.sdf
```

### Terminal 2 — Gazebo GUI

```bash
source /opt/ros/jazzy/setup.bash
export GZ_PARTITION=robotics_test
export GZ_IP=127.0.0.1
export QT_QPA_PLATFORM=xcb
export GZ_SIM_RESOURCE_PATH="/opt/ros/jazzy/share/turtlebot3_gazebo/models:${GZ_SIM_RESOURCE_PATH:-}"

gz sim -g -v 4
```

Using the X11-compatible Qt backend (`xcb`) helped the GUI render on the original Ubuntu/Wayland setup.

## 7. Spawn TurtleBot3 Burger

Keep the Gazebo server and GUI running. Open a third terminal:

```bash
source /opt/ros/jazzy/setup.bash
export GZ_PARTITION=robotics_test
export GZ_IP=127.0.0.1
export TURTLEBOT3_MODEL=burger
export GZ_SIM_RESOURCE_PATH="/opt/ros/jazzy/share/turtlebot3_gazebo/models:${GZ_SIM_RESOURCE_PATH:-}"

ros2 launch turtlebot3_gazebo spawn_turtlebot3.launch.py \
  x_pose:=-0.75 y_pose:=-1.25
```

The initial coordinates are for the current development maze. Confirm the chosen spawn point is free of walls; adjust `x_pose` and `y_pose` if required.

The official launch file uses `ros_gz_sim/create` to spawn `turtlebot3_burger/model.sdf` and starts the ROS–Gazebo parameter bridge.

## 8. Verify robot topics and sensors

In another terminal:

```bash
source /opt/ros/jazzy/setup.bash
ros2 topic list | grep -E 'scan|odom|cmd_vel|joint_states'
```

Expected topics:

```text
/cmd_vel
/joint_states
/odom
/scan
```

Confirm that the topics have live data and inspect the velocity message type:

```bash
ros2 topic hz /scan                 # Ctrl+C after a few readings
ros2 topic echo /odom --once
ros2 topic info /cmd_vel -v
```

Only topic **discovery** has been verified so far. LiDAR rate, odometry updates, and controlled robot motion are the next checks. Do not send manual `/cmd_vel` commands until its message type and subscriber are confirmed.
